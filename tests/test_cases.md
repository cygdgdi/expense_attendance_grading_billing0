## Bugs Found and Fixed

The first version of the code was tested against the Client Requirements Specification (CRS). These differences were found and fixed.

| #  | Bug found                                                                         | Fix                                                                                                           | CRS reference           |
|----|-----------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------|-------------------------|
| 1  | Ctrl+C ended the program with a `KeyboardInterrupt` traceback                     | `main.py` now catches `KeyboardInterrupt` and `EOFError` and exits with a goodbye message                     | Section 11, TC-20       |
| 2  | A numeric-only attendance ID such as `101` was rejected ("Name cannot be empty.") | New `get_id()` accepts letters and digits                                                                     | FR-21                   |
| 3  | Names such as `A` or `A1` were accepted                                           | `get_name()` now requires letters and spaces only, 2–40 characters                                            | Section 7 (Name)        |
| 4  | Number of subjects had no default                                                 | Pressing Enter now uses 5                                                                                     | FR-30                   |
| 5  | Error messages did not match the CRS ("Value is too small…")                      | Each field now shows the exact CRS message, e.g. "Invalid choice. Enter 1-6."                                 | Section 7               |
| 6  | Invoice had no date; report card showed `439.00` instead of `439 / 500`           | Date line added, discount shown as `Discount (5%)  -137.50`, report card shows `439 / 500`                    | Sections 6.4, 6.5       |
| 7  | No separate report per module and no file export                                  | Reports sub-menu (Expense / Attendance / Grading / Billing / All) with optional `.txt` export                 | FR-50, FR-53            |
| 8  | Conversions used `isdigit()` checks only                                          | `get_int()` / `get_float()` now use `try / except ValueError`; added `get_choice()`, `get_id()`, `get_text()` | Sections 9.1, 11        |
| 9  | Money was only rounded when printed                                               | Discount, tax and totals are rounded to 2 decimals when calculated                                            | NFR-07                  |
| 10 | Thresholds were hard-coded in the logic                                           | `TAX_RATE`, `PASS_MARK`, attendance thresholds and discount slabs are constants at the top of their files     | Section 15              |
| 11 | Nothing reminded the user that data is lost on exit                               | A `finally` block prints a session line on every exit (normal or Ctrl+C)                                      | Section 9.1, Section 15 |
